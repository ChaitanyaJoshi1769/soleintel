# Railway Deployment Guide

## Overview
This guide covers deploying SOLEINTEL API to Railway.app with automatic CI/CD, database, and monitoring.

## Prerequisites

1. **Railway Account**: https://railway.app (free tier available)
2. **GitHub Repository**: Linked to your Railway project
3. **Database**: PostgreSQL (provided by Railway)
4. **Environment Variables**: Ready to configure
5. **Sentry Account**: https://sentry.io (for error tracking)

## Step 1: Create Railway Project

1. Log in to [Railway Dashboard](https://railway.app/dashboard)
2. Click "New Project"
3. Select "Deploy from GitHub repo"
4. Authorize Railway to access your GitHub
5. Select `soleintel` repository
6. Select `feat/week-3-production` branch (or main)

## Step 2: Configure Services

### PostgreSQL Database
1. Click "Add Service" → "Database" → "PostgreSQL"
2. Accept default configuration (12GB storage free tier)
3. Railway automatically creates `DATABASE_URL`

### Redis Cache (Optional but recommended)
1. Click "Add Service" → "Database" → "Redis"
2. Accept default configuration
3. Railway automatically creates `REDIS_URL`

### API Service
Railway auto-detects Node.js application in `apps/api/`.

## Step 3: Configure Environment Variables

In Railway Dashboard, go to "Variables" for the API service:

```
# Core Settings
NODE_ENV=production
PORT=3000
LOG_LEVEL=info

# Database (auto-generated by Railway)
DATABASE_URL=${{ DATABASE_URL }}
REDIS_URL=${{ REDIS_URL }}

# API Configuration
CORS_ORIGIN=https://soleintel.com,https://extension.soleintel.com
API_BASE_URL=https://soleintel-api.railway.app

# Price Tracking
ENABLE_PRICE_TRACKING=true
PRICE_TRACKING_INTERVAL=360

# Sentry Error Tracking
SENTRY_DSN=https://[key]@[sentry-id].ingest.sentry.io/[project-id]

# Email Notifications
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-app-password
SMTP_FROM=noreply@soleintel.com

# OpenAI (for GPT-4 insights)
OPENAI_API_KEY=sk-...

# Optional: Monitoring
DATADOG_API_KEY=...
DATADOG_APP_KEY=...
```

## Step 4: Configure Build Settings

Railway auto-detects from `railway.json`:

Build Command:
```
pnpm install && pnpm build
```

Start Command:
```
pnpm start
```

If not auto-detected, set manually:
1. Go to "Settings" → "Build"
2. Paste commands above

## Step 5: Configure Domain

### Get Railway Domain
1. Go to "Settings" → "Networking"
2. Railway provides: `your-project-xyz.railway.app`
3. This is your API endpoint

### Custom Domain (Optional)
1. Go to "Settings" → "Networking"
2. Click "Add Custom Domain"
3. Add: `api.soleintel.com`
4. Update DNS records at your registrar:
   ```
   CNAME  api.soleintel.com  your-project-xyz.railway.app
   ```
5. SSL certificate auto-generated by Railway

## Step 6: Setup Error Tracking (Sentry)

### Create Sentry Project
1. Sign up at https://sentry.io
2. Create new project: Node.js
3. Get your DSN: `https://[key]@[id].ingest.sentry.io/[project]`
4. Add to Railway environment variables: `SENTRY_DSN`

### Configure Alerts
In Sentry:
1. Go to "Alerts" → "Create Alert Rule"
2. Alert on: "Issues in any project"
3. Condition: "An issue is seen {count} times in {window}"
4. Set: "3 times in 15 minutes"
5. Action: Send to Slack/Email/PagerDuty

### Verify Integration
After deployment:
```bash
curl https://api.soleintel.com/health
# Should return: { "status": "ok", "timestamp": "..." }
```

## Step 7: Database Migrations

### Run Migrations
Railway runs migrations automatically if configured in `package.json`:

```json
{
  "scripts": {
    "migrate": "prisma migrate deploy",
    "seed": "prisma db seed"
  }
}
```

### First Time Setup
1. Go to "Deploy Logs" tab
2. Verify "prisma migrate deploy" ran successfully
3. Check database in Railway Console:
   ```sql
   SELECT COUNT(*) FROM information_schema.tables 
   WHERE table_schema = 'public';
   ```

## Step 8: Configure Auto-Deployment

### GitHub Integration (default)
- Every push to `main` automatically deploys
- Pull request previews auto-generated

### Configure Deployment Rules
1. Go to "Settings" → "Deployment"
2. Auto-deploy from: `main` branch
3. Ignore builds: `.md` files (optional)

## Step 9: Monitoring & Alerts

### Railway Metrics
1. Go to "Monitoring" tab
2. View CPU, memory, disk usage
3. Check request metrics

### Set Up Alerts
1. Go to "Settings" → "Alerts"
2. Create alert for:
   - CPU > 80% for 5 minutes
   - Memory > 90% for 5 minutes
   - Deploy failures

### Logs
View logs in "Deploy Logs" tab:
```bash
# Filter by service
logs: {"service": "api"}

# Search for errors
logs: {"level": "error"}

# Real-time tail
pnpm logs
```

## Step 10: Backup & Recovery

### Database Backups
Railway auto-backs up PostgreSQL:
- Retention: 7 days (free tier)
- Daily backups
- Download backup from Dashboard

### Restore from Backup
1. Go to PostgreSQL service → "Backups"
2. Click "Restore" on desired backup
3. Creates new database (manual restore needed)

## Common Issues & Solutions

### Build Fails
```
Error: Cannot find module '@soleintel/xyz'
```
**Solution**: Ensure monorepo dependencies are linked:
```bash
pnpm install
pnpm build
```

### Database Connection Fails
```
Error: connect ECONNREFUSED 127.0.0.1:5432
```
**Solution**: 
1. Verify `DATABASE_URL` set in Railway variables
2. Ensure PostgreSQL service started
3. Check Prisma: `prisma db push`

### Out of Memory
```
JavaScript heap out of memory
```
**Solution**:
1. Increase Railway memory limit (paid tier)
2. Optimize database queries
3. Add Redis caching

### Deployment Hangs
**Solution**:
1. Check build logs for long-running tasks
2. Add timeout environment: `BUILD_TIMEOUT=900`
3. Split large tasks into smaller ones

## Performance Tuning

### Database Optimization
```sql
-- Create indexes for common queries
CREATE INDEX idx_product_sku ON products(sku);
CREATE INDEX idx_retailer_listing_price ON retailer_listings(price);
CREATE INDEX idx_price_history_date ON price_history(date);
```

### API Optimization
1. Enable query caching with Redis
2. Implement response compression
3. Use connection pooling

### Monitoring Performance
- Response times in Sentry → Performance tab
- Database query metrics in Railway Console
- CPU/memory trends over time

## Rollback Procedure

If deployment has issues:
1. Go to "Deployments" tab
2. Find previous successful deployment
3. Click "Rollback"
4. Confirm rollback
5. Old version deployed in ~2 minutes
